# CARD-039 Executar o checklist da seção 8.3 e entregar no SIGAA

**Tipo:** Task  
**Prioridade:** Alta

## Descrição

Conferir, item a item, o checklist de entrega da seção 8.3 do documento do professor e realizar a entrega no SIGAA, informando o link do repositório público e os nomes completos dos integrantes, dentro do prazo.

**Prazo: 08/11/2026, até 23h59.** A entrega ocorre exclusivamente pelo SIGAA.

## Requisitos relacionados

- ENT01: prazo de entrega até 08/11/2026, 23h59.
- ENT02: entrega exclusivamente pelo SIGAA, com o link do repositório e os nomes completos dos integrantes.
- ENT03: o projeto deve estar funcional e disponível para avaliação.
- ENT06: cumprir o checklist de entrega da seção 8.3.
- ENT07: ciência das penalidades da seção 8.4.
- EQ01: equipes de até 4 estudantes.

## Critérios de aceitação

- [ ] O repositório está público e acessível no GitHub.
- [ ] O `README.md` contém os nomes completos de todos os integrantes.
- [ ] O `README.md` apresenta as instruções para configuração e execução.
- [ ] O código-fonte e todos os arquivos necessários estão disponíveis.
- [ ] As chaves de API e demais parâmetros necessários à integração com a nuvem foram disponibilizados.
- [ ] O serviço de armazenamento em nuvem está acessível e funcionando, conferido no dia da entrega.
- [ ] A aplicação pode ser compilada e executada a partir do repositório (CARD-038 concluído).
- [ ] O repositório não contém artefatos de compilação, executáveis ou arquivos gerados desnecessários (CARD-034 concluído).
- [ ] O projeto foi formatado com `dart format .` e verificado com `flutter analyze` após a última alteração de código.
- [ ] O link do repositório e os nomes completos dos integrantes foram informados no SIGAA antes de 08/11/2026, 23h59.
- [ ] O comprovante da entrega no SIGAA foi salvo.
- [ ] Todos os integrantes confirmaram a entrega.

## Observações técnicas

Fazer a entrega com folga em relação ao prazo, pois falhas de acesso ao SIGAA ou instabilidade no serviço de nuvem podem ocorrer perto do horário-limite. Após a entrega, evitar alterações no repositório que possam quebrar a execução, já que o avaliador usará o que estiver publicado. O documento não define essa regra, e a recomendação é uma precaução da equipe.
